Build learn-better with an AI assistant

A hands-on, 9-lesson course that takes you from an empty folder to a full toolkit that turns YouTube content into study material (audio, transcripts, summaries, word clouds, narrated audio) — all free and no-API-key. You build it by collaborating with an AI coding assistant, learning how to prompt, review, correct, and iterate.

Assistant-agnostic. The lessons say "your AI assistant" and work with any harness (Kiro, Claude, or another). Every step gives a plain-language instruction and a ready-to-paste example prompt, plus a Verify check. Source: the Markdown lessons in this folder — each card below links to the full lesson.

Lesson 02

Your first working tool (early win)

★★~45–75 min

Goal
A no-API-key script (code/read_channel.py) that lists a YouTube source and downloads a clip's audio + transcript into data/ — a real file on disk. Plus the core skill: feed an error back and iterate.
Sample prompt (plan first)
"Before writing anything, list the file(s) and behavior. I want ONE script code/read_channel.py: reads a source at the top (playlist/channel/search + LIMIT); saves transcript + audio to data/; SKIPS what exists; flags clips with no transcript. No API key. Confirm the plan; don't code yet."
Iterate-and-fix
"Running it gave this exact output: <paste full error>. What's the root cause, and the smallest fix? Explain the cause first." → and, after two failed patches: "Step back — what's the actual root cause, and is there a fundamentally different approach?"
Check
dir data\audio / ls -R data shows an .mp3 + a .txt. A second run skips them. git status shows code, not the media (it's under ignored data/).
You'll have code/read_channel.py; data/audio/ + data/transcripts/ with real files — your first working tool.

Getting the environment right (properly)

★★~45–60 min

Goal

Sample prompt
"Compare conda vs pip+venv vs uv for a Python 3.12 project that also needs ffmpeg, on <OS>. Short pros/cons each + a one-line recommendation. Note explicitly which can install ffmpeg and which can't."

Troubleshooting your AI — the recap

Every lesson has a "When the AI misbehaves" box; Lesson 09 gathers them. Assume your assistant rarely hard-crashes — these are the everyday snags and the move that fixes each.

  • It stalls / goes silent → wait, then "are you still there? continue"; for a lost thread, paste the lesson's Re-orient the AI block.
  • A file write got interrupted → verify the file isn't half-written before building on it.
  • Wrong Python interpreter/env (ModuleNotFoundError after installing) → python -c "import sys; print(sys.executable)"; activate your env.
  • Terminal output looks empty/garbled → trust the artifact (a file under data/), not the console.
  • Bot-check / 429 from YouTube → not a code bug; cookies file, or wait & retry, or fetch fewer languages.
  • It over-produces (150-line .gitignore, extra deps) → "minimal", "only what's used".
  • A refactor changes behavior → require verified sameness: change the source of truth first, then re-run + git status.
  • .sh fails on Linux (^M) → CRLF endings; fix via .gitattributes (*.sh eol=lf).
  • Container won't build → usually ffmpeg missing from the image, or a retired base image (404).
  • Change approach, don't re-patch → after two failed fixes on one approach, ask for the root cause + a different approach.
  • Feed back exact errors → the single habit that beats everything: paste the real output, ask for a diagnosis before a patch.
